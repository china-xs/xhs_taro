# Repository Guidelines

## Project Structure & Module Organization
- `src/` holds application code. Entry files are `src/app.ts`, `src/app.config.ts`, and global styles in `src/app.scss`.
- `src/pages/` contains page modules; each page lives in its own folder (for example, `src/pages/index/` with `index.vue`, `index.config.ts`, and `index.scss`).
- `__tests__/` contains Jest tests (see `__tests__/index.test.js`).
- `config/` stores environment-specific build config (`config/dev.ts`, `config/prod.ts`).
- `dist/` is a build output directory generated by Taro.

## Build, Test, and Development Commands
- `npm run dev:xhs`: watch build for the Xiaohongshu miniapp target.
- `npm run build:xhs`: production build for the Xiaohongshu target.
- `npm run dev:weapp`: watch build for WeChat miniapp (other targets include `dev:alipay`, `dev:tt`, `dev:h5`).
- `npm test`: run Jest tests with the Taro Vue3 preset.

## Coding Style & Naming Conventions
- Indentation: 2 spaces, enforced by `.editorconfig`.
- Vue 3 Single File Components live in `*.vue` files; page-level styles use `*.scss`.
- ESLint config extends `taro/vue3` via `.eslintrc`.
- Keep file names aligned with page folders (for example, `pages/foo/foo.vue` + `foo.config.ts`).

## Testing Guidelines
- Test framework: Jest (`jest.config.ts`) with `jsdom`.
- Naming pattern: `__tests__/**/*.(spec|test).[jt]s?(x)`.
- Run tests with `npm test` before shipping changes.

## Commit & Pull Request Guidelines
- Git history is minimal and does not show a formal commit convention; keep messages short and descriptive (example: `init taro vue sass`).
- PRs should include: summary of changes, target platform(s) tested (for example, `xhs` or `weapp`), and screenshots or recordings for UI changes.

## Configuration & Environment Notes
- Platform builds are configured through Taro CLI; choose the correct target via `npm run build:<target>`.
- Update `project.*.json` only when platform-specific settings change.
